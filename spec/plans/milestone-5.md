## 5. שלב ב – בדיקה מקיפה מקומית (מול Development)

`npm run lint`, `npm run build`, ואז `npm run dev` ובדיקה בדפדפן המובנה, ב-Desktop וברוחב 375px, בשלוש השפות. אחרי שינוי שפה בודקים שוב כל מסך.

1. **M1:** עיצוב מסך Поиск, תלות מדינה ← עיר, Найти מושבת עד שהשדות מלאים, החלפת שפה ו-`lang`, ניווט עם פריט פעיל, בלי גלילה אופקית.
2. **M2:** 3 חיפושים לפחות (כולל עיר במולדובה) – עד 5 ספקים, מלאים לפני חלקיים, תג וסטטוס לכל תנאי, קישורי מקורות נפתחים, «Нет данных». מצבי טעינה, «פחות מ-5», «לא נמצאו», שגיאה עם «Повторить» (Offline בדפדפן). חיפוש חדש תוך כדי חיפוש. קלט מחוץ לקטלוג ← `400`. אין מפתח API ב-Bundle (חיפוש ב-`.next/static`).
3. **M3:** ייצוא ל-Excel – פתיחת הקובץ ובדיקת התוכן, כותרות ב-EN/UK, אין כפתור כשאין ספקים, רשימה ריקה ← `400`.
4. **M4:** שמירה ← «Новый» ו-«Сохранено», גם בחיפוש חוזר. אין כפילות. סטטוס, הערה (מגבלת 1,000) ומחיקה עם אישור נשמרים אחרי ריענון. שתי לשוניות רואות את אותו מצב. כשל שמירה ועדכון של ספק שנמחק. סינון לפי עיר ותחום, כולל אחרי ריענון. ייצוא הרשימה השמורה.
5. **מקרי הקצה של PRD 4ב** – עוברים על הטבלה שורה-שורה ומסמנים מה נבדק.

בסוף: מחיקת נתוני הבדיקה שלי מטבלת ה-Development (אחרי שאני שואל), וסגירת השרת.

## 6. שלב ג – בדיקה בכתובת ה-Production

עושים את אותן בדיקות כמו בשלב ב, בכתובת ה-Production. **כל פעולה שכותבת נתונים ב-Production (שמירה, עדכון, מחיקה) – רק אחרי אישור המשתמשת.** בנוסף, הסעיפים שאפשר לבדוק רק ב-Production:

| סעיף | איך נבדק | מי |
|---|---|---|
| Push ל-`main` מפרסם אוטומטית (M1) | ה-Deployment האחרון ב-Vercel נוצר מהקומיט האחרון | אני / המשתמשת |
| התקנה כ-PWA ב-Android ופתיחה במסך מלא (M1) | Chrome ב-Android ← "התקנה" ← פתיחה מהאייקון | המשתמשת, לפי הוראות שאתן |
| חריגה מ-Rate Limiting ← `429` (M2, M4) | שליחת הרבה בקשות ברצף ל-`/api/search` עם קלט לא תקין (נדחה ב-`400` בלי עלות OpenAI) ול-`GET /api/saved-suppliers`, עד שמתקבל `429` | אני, באישור המשתמשת |
| הורדת Excel ב-Android, גם מהאפליקציה המותקנת (M3) | ייצוא תוצאות וייצוא רשימה שמורה מהנייד | המשתמשת |
| שינוי במכשיר אחד נראה באחר (M4) | שינוי סטטוס במחשב ← ריענון בנייד | המשתמשת |
| Production משתמש ב-`prod` של OpenAI וב-`suppliers-prod` | אחרי חיפוש ב-Production: השימוש מופיע ב-OpenAI Usage של Project ‏`prod`; אחרי שמירה: השורה מופיעה בטבלה של `suppliers-prod` ולא של `suppliers-dev` | המשתמשת (ואני דרך החיבור ל-Supabase, קריאה בלבד) |

**Smoke ב-Production:** חיפוש אמיתי ← ייצוא ← שמירה ← ריענון ← שינוי סטטוס והערה ← מחיקה.

**נתוני הבדיקה ב-Production:** בסוף שלב ג אציג למשתמשת אילו ספקים נשמרו בבדיקה, והיא תבחר: למחוק אותם (דרך כפתור «Удалить» באתר), או להשאיר אותם כחלק מנתוני ההדגמה.

## 8. שלב ה – `DEMO.md`

קובץ בעברית (טקסטי הממשק מצוטטים ברוסית, כפי שהם מופיעים במסך), במבנה של חמשת החלקים מ-MILESTONES.md:

1. **הרעיון** – מטרה, בעיה וקהל יעד, בכמה משפטים מ-PRD סעיפים 1–2.
2. **הדגמת יכולות הליבה** – צעד אחר צעד: חיפוש (כולל מה להראות בכרטיס: צ'יפים של תנאי הסף, מקורות, תג "לא כל התנאים"), שמירה, עדכון סטטוס והערה, מחיקה, ייצוא ל-Excel (מהתוצאות ומהרשימה השמורה), החלפת שפה. לכל צעד: מה לוחצים ומה אמור להופיע.
3. **הוכחת שמירה** – שמירה/עדכון באתר ← הצגת השורה בטבלה `saved_suppliers` ב-Dashboard של `suppliers-prod` (Table Editor) ← ריענון הדף ← המצב נשאר.
4. **האוטומציה המתוכננת** – תקציר של PRD 6ב: בעיה, טריגר שבועי, פעולה, תוצאה.
5. **תכנון ההמשך** – טבלת היכולות מ-PRD 6ג.

בנוסף, בתחילת הקובץ:
- **רשימת הכנה לבוקר ההדגמה:** `suppliers-prod` פעיל (ADR-8), האתר נפתח, לשונית פתוחה של Supabase Table Editor, הצירופים עם נתוני ההדגמה.
- **תוכנית גיבוי:** אם החיפוש החי איטי או נכשל – ממשיכים עם נתוני ההדגמה השמורים (צפייה, עדכון, מחיקה, ייצוא).
- **זמן החיפוש שנמדד בחזרה** (מתמלא בשלב ו).

## 12. החלטות פרשנות – אושרו על ידי המשתמשת (כל ארבע ההצעות)

1. **מי מזין את נתוני ההדגמה ב-Production?** הצעה: אני, דרך הדפדפן המובנה באתר ה-Production, אחרי אישור שלך – ואת רואה הכול על המסך. חלופה: את מזינה בעצמך לפי רשימה שאכין.
2. **שפת `DEMO.md`:** הצעה: עברית, עם טקסטי הממשק ברוסית כפי שהם מופיעים במסך.
3. **"סעיף 5 בדרישות ההגשה"** – מסמך דרישות ההגשה לא נמצא ב-Repository. אני בונה את התסריט לפי חמשת החלקים שמפורטים ב-MILESTONES.md. אם יש במסמך המקורי דרישות נוספות (למשל משך מקסימלי להצגה) – כדאי לשתף אותן לפני הבנייה.
4. **בדיקות דרך החיבורים ל-Vercel ול-Supabase:** הצעה: אני קורא (בלבד) שמות משתני סביבה, כללי Firewall, סטטוס Deployments וטבלאות/Migrations ב-Production, כדי לחסוך לך צעדים. שום שינוי בהגדרות או בנתונים דרכם.
